# Homelab

Учебный стенд для знакомства с Linux, Docker, Kubernetes, Prometheus и Grafana.

Поднял Ubuntu в VirtualBox. Написал небольшое API, собрал Docker-образ и загрузил его в Docker Hub. После этого запустил приложение в Kubernetes и настроил сбор метрик.

Код и файлы редактирую в Windows через VS Code. Изменения отправляю на GitHub, а на Ubuntu забираю через Git. С сервером работаю по SSH.

[Репозиторий на GitHub](https://github.com/375f/homelab) · [Образ в Docker Hub](https://hub.docker.com/r/panda975/homelab)

## На чём всё работает

Для стенда использовал одну виртуальную машину:

| Параметр | Значение |
| --- | --- |
| ОС | Ubuntu Server 24.04 LTS |
| Оперативная память | 4 ГБ |
| Процессор | 2 CPU |
| Диск | 30 ГБ |
| Виртуализация | VirtualBox |
| Kubernetes | K3s, один узел |

В VirtualBox настроил NAT и проброс портов: `127.0.0.1:2222` на Windows ведёт на порт `22` Ubuntu. Через него подключаюсь по SSH.

Это мой homelab: домашний стенд, на котором можно пробовать настройки и разбирать ошибки.

## Что сделал

- Настроил Ubuntu и SSH. Проверил процессы, память, диск, сетевые интерфейсы и логи SSH.
- Создал Git-репозиторий. Попрактиковался с `add`, `commit`, `push`, `fetch` и `pull`.

- Загрузил образ `panda975/homelab:0.1.0` в Docker Hub.

## Как устроено приложение

API написано на Python с Flask. В контейнере его запускает Gunicorn. Для метрик использовал `prometheus-client`.

| Адрес | Что возвращает |
| --- | --- |
| `/` | Сообщение, версию приложения и имя контейнера |
| `/health` | Ответ `200` и статус `ok` |
| `/error` | Специально созданную ошибку `500` для проверки мониторинга |
| `/metrics` | Метрики в формате Prometheus |

В Kubernetes приложение работает в namespace `homelab`. Deployment поддерживает две реплики, а Service направляет запросы на готовые Pod'ы. При нескольких запросах к `/` можно увидеть разные имена в поле `hostname`.

Prometheus отдельно собирает метрики с каждой копии приложения. Grafana обращается к Prometheus и показывает полученные значения на дашборде.

Docker использовал для сборки и первого запуска образа. В K3s контейнеры запускаются через containerd. Поэтому Pod'ы смотрю через `kubectl`, а не через `docker ps`.

## Как запускаю стенд после выключения

Сначала запускаю Ubuntu в VirtualBox. Затем в PowerShell на Windows подключаюсь к серверу:

```powershell
ssh -p 2222 devops@127.0.0.1
```

После подключения выполняю команды уже на Ubuntu:

```bash
sudo systemctl is-active k3s
sudo k3s kubectl get nodes
sudo k3s kubectl -n homelab get pods
```

K3s запускается вместе с Ubuntu. Заново собирать образ и применять манифесты после обычного выключения не нужно. Жду, пока узел станет `Ready`, а Pod'ы приложения, Prometheus и Grafana будут готовы.

Чтобы открыть Grafana, в SSH-сессии запускаю:

```bash
sudo k3s kubectl -n homelab port-forward service/grafana 3000:3000
```

Это окно оставляю открытым. В отдельном PowerShell на Windows запускаю SSH-туннель:

```powershell
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:13000:127.0.0.1:3000 -p 2222 devops@127.0.0.1
```

Теперь Grafana доступна в браузере по адресу [http://127.0.0.1:13000](http://127.0.0.1:13000). Пока пользуюсь ей, оба окна с пробросом портов должны оставаться открытыми.

## Как проверяю API

В отдельной SSH-сессии на Ubuntu получаю адрес Service и отправляю запросы:

```bash
homelab_service_ip=$(sudo k3s kubectl -n homelab get service homelab-api -o jsonpath='{.spec.clusterIP}')

curl -i "http://${homelab_service_ip}/"
curl -i "http://${homelab_service_ip}/health"
curl -i "http://${homelab_service_ip}/error"
```

Первые два запроса должны вернуть `200`, а `/error` должен вернуть `500`. Здесь ошибка создана специально.

Для графика отправляю запросы в течение минуты:

```bash
for i in {1..60}; do
  curl -sS -o /dev/null -w 'HTTP %{http_code}\n' "http://${homelab_service_ip}/"
  sleep 1
done
```

Если заменить `/` на `/error`, на графике появятся запросы со статусом `500`.

## Что показывает Grafana

На дашборде `homelab` сделал две панели. Поставил период `Last 15 minutes` и обновление каждые `5s`.

Панель «Сбор метрик с API» использует запрос:

```promql
up{job="homelab-api"}
```

Для каждой копии приложения показывается своё значение. `1` означает, что Prometheus успешно собрал метрики. Даже когда `/error` возвращает `500`, здесь может оставаться `1`: сбор метрик продолжает работать.

Панель «Запросы в секунду» использует запрос:

```promql
sum by (status) (
  rate(homelab_requests_total{job="homelab-api"}[1m])
)
```

Он считает среднее количество запросов в секунду за последнюю минуту и складывает значения с обеих копий приложения. Для ответов `200` и `500` получаются отдельные линии. Запросы к `/health` и `/metrics` в этот счётчик не входят.

## Разбор ошибки ImagePullBackOff

Специально попробовал обновить приложение на образ `panda975/homelab:training-missing`. Такого тега в Docker Hub не было.

Обновление не завершалось. Через `get pods` нашёл новый Pod с `ImagePullBackOff`, затем через `describe pod` посмотрел Events. В сообщении было `not found`: Kubernetes не смог скачать образ с указанным тегом.

Выполнил откат к предыдущей версии:

```bash
sudo k3s kubectl -n homelab rollout undo deployment/homelab-api
sudo k3s kubectl -n homelab rollout status deployment/homelab-api --timeout=120s
```

После отката проверил состояние:

```bash
sudo k3s kubectl -n homelab get deployment homelab-api
sudo k3s kubectl -n homelab get pods
```

Deployment снова показал `2/2`, оба Pod'а были готовы. Запрос к API вернул `200` и версию `0.1.0`.

В этом случае Kubernetes сам не выбрал предыдущий образ. Он продолжал пытаться скачать указанный образ, а откат выполнил я.

## Как передаю изменения

После редактирования файлов в VS Code проверяю изменения, добавляю нужные файлы через `git add`, делаю `git commit` и `git push`.

На Ubuntu забираю изменения:

```bash
cd ~/homelab
git pull --ff-only
```

Git передаёт файлы. Само приложение от этого не обновляется. Для изменений в коде нужно собрать и отправить новый образ, указать его тег в манифесте и применить манифест. Настройки Kubernetes применяю через `kubectl apply -f` с нужным файлом из папки `k8s`.

## Как выключаю

Останавливаю пробросы портов через `Ctrl+C`. В SSH-сессии на Ubuntu выполняю:

```bash
sudo poweroff
```

Жду, пока виртуальная машина выключится. Отдельно удалять Pod'ы или останавливать Prometheus и Grafana перед этим не нужно.

## Что пока ограничено

Весь стенд работает на одной виртуальной машине. Две копии API позволяют проверить работу реплик, но при выключении этой машины недоступно всё приложение.

Данные Grafana хранятся на PVC. У Prometheus используется `emptyDir`, поэтому при пересоздании его Pod'а история метрик теряется.

С Grafana пока разбираюсь. На этом стенде проверил сбор метрик, графики успешных запросов и ошибок. CI/CD и Ansible в проект пока не добавлял.
